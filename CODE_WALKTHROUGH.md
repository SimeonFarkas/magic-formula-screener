### 1.1 `docker-compose.yml`:
Defines and configures a local PostgreSQL 16 database inside a Docker container so the Java application can store and query data without installing PostgreSQL directly on the host machine.
- **`services.postgres`** — Lists the background programs Docker should run. Here, we only need one: a database called `postgres`.
- **`image: postgres:16-alpine`** — The blueprint Docker downloads to build the container. It uses PostgreSQL 16 on Alpine Linux, a lightweight operating system that keeps the download small and startup fast.
- **`container_name: mfs-postgres`** — Gives the container a fixed, easy-to-find name instead of a random nickname generated by Docker.
- **`restart: unless-stopped`** — Automatically restarts the database if it crashes or when you reboot your computer, unless you intentionally stop it yourself.
- **`environment`** — Sets up the database name (`POSTGRES_DB`), username (`POSTGRES_USER`), and password (`POSTGRES_PASSWORD`) the very first time the container starts. The `${...}` syntax pulls these values from your private `.env` file so your passwords stay out of Git.
- **`ports: "${POSTGRES_PORT}:5432"`** — Opens a doorway between your computer and the container. PostgreSQL listens on port `5432` inside the container, and this connects it to your chosen port on `localhost` so `Main.java` and Flyway can talk to it.
- **`volumes` (`postgres_data:/var/lib/postgresql/data` & bottom `volumes:` block)** — Containers are temporary by design: if you delete or rebuild one, everything inside resets. Connecting PostgreSQL's internal data folder to a saved storage space (`mfs_postgres_data`) ensures your tables and saved companies stay safe on your hard drive across restarts.
- **`healthcheck`** — Runs `pg_isready` every 5 seconds (up to 5 tries, waiting up to 5 seconds per check) to verify that PostgreSQL is actually awake and ready to accept connections—not just starting up.

### 1.2 `pom.xml`:
`pom.xml` (Project Object Model) is Maven's instruction manual and shopping list for your project. It tells Maven which version of Java to use, which external libraries to download, and how to compile, run, and test your application.

#### 1. Project Identity & Settings
- **`groupId`, `artifactId`, `version`** — Gives your project a unique ID (`io.github.simeonfarkas:magic-formula-screener:1.0-SNAPSHOT`). `SNAPSHOT` means it is still under active development.
- **`maven.compiler.release` (`21`)** — Sets the Java version to **Java 21**, enabling modern features like Java `record` classes and multi-line SQL text blocks (`"""`).
- **`project.build.sourceEncoding` (`UTF-8`)** — Ensures text encoding is consistent everywhere so Swedish characters (`Å`, `Ä`, `Ö`) in Nasdaq Stockholm company names never get corrupted.

#### 2. Dependencies (External Libraries)
Instead of writing everything from scratch, Maven downloads these ready-made toolkits for you:

- **Database & Connection Pooling**
  - **`postgresql`** — The JDBC driver that allows Java to connect to and talk with a PostgreSQL database.
  - **`HikariCP`** — A connection pool. Opening a new database connection from scratch is slow; HikariCP keeps a small set of open connections ready to reuse.
- **Database Migrations**
  - **`flyway-core` & `flyway-database-postgresql`** — Reads your `V1__...` and `V2__...` SQL files and applies them to PostgreSQL in order. (Flyway 10+ requires the separate PostgreSQL extension module alongside `flyway-core`.)
- **Logging**
  - **`slf4j-api` & `logback-classic`** — Provides structured logging for your app and libraries like HikariCP, Flyway, and Testcontainers.
- **JSON Serialization & Deserialization**
  - **`jackson-databind`** — Converts raw JSON responses from the stock data API directly into Java `record` DTOs.
  - **`jackson-datatype-jsr310`** — Adds support for modern Java date/time types (`LocalDate`, `Instant`) so Jackson can parse JSON date strings like `"2025-12-31"`.
- **Testing (`<scope>test</scope>`)** — *Only used when running tests; excluded from the main application:*
  - **`junit-jupiter`** — The JUnit 5 testing framework that discovers and runs your `@Test` methods.
  - **`assertj-core`** — Provides readable, human-friendly test checks (e.g., `assertThat(company).isPresent()`).
  - **`testcontainers` (`postgresql` & `junit-jupiter`)** — Spins up a temporary, throwaway PostgreSQL Docker container during tests so you can verify your real SQL queries without touching your development database.

#### 3. Build Plugins (Maven Commands)
Plugins add actions you can trigger from the terminal or IntelliJ:
- **`maven-compiler-plugin`** — Translates your `.java` files into runnable Java 21 bytecode.
- **`exec-maven-plugin`** — Lets you run `io.github.simeonfarkas.Main` directly with `mvn exec:java`, automatically including all downloaded dependencies.
- **`maven-surefire-plugin`** — Runs your JUnit 5 test suite when you execute `mvn test`, and sets `-Dapi.version=1.44` so Testcontainers communicates smoothly with Docker.
- **`flyway-maven-plugin`** — Lets you run database migrations straight from the command line (`mvn flyway:migrate`) against `jdbc:postgresql://localhost:5432/magic_formula_dev` without having to run `Main.java`.

<summary><h2 style="display: inline;">2. Database Migrations</h2></summary>

### 2.1 `V1__create_companies_table.sql`:
This is the first Flyway migration script. When the application starts up, Flyway runs this file once to build the `companies` table in PostgreSQL where all Nasdaq Stockholm listed companies are stored.
#### Column-by-Column Breakdown
- **`id BIGSERIAL PRIMARY KEY`** — Automatically generates a unique, auto-incrementing number (`1, 2, 3...`) for every company saved.
- **`ticker VARCHAR(12) NOT NULL UNIQUE`** — Stores the stock symbol (such as `VOLV-B`). `UNIQUE` prevents duplicate companies and enables `ON CONFLICT (ticker) DO UPDATE`.
- **`name VARCHAR(255) NOT NULL`** — Stores the company's full name.
- **`sector VARCHAR(100)` & `industry VARCHAR(100)`** — Optional text fields for categorizing what the company does, useful for filtering out financial and utility stocks later.
- **`currency VARCHAR(3) NOT NULL`** — Stores the 3-letter currency code (such as `SEK`).
- **`is_active BOOLEAN NOT NULL DEFAULT TRUE`** — Tracks whether the company is still actively listed on the exchange.
- **`created_at` & `updated_at`** — Automatically records the exact date and time a row was created and modified.

#### Index
- **`CREATE INDEX idx_companies_sector ON companies(sector);`** — Builds a fast lookup shortcut on the `sector` column.

### 2.2 `V2__create_company_and_metric_tables.sql`:
This second Flyway migration updates your database schema after `V1`.

#### 1. Extending the `companies` Table (`ALTER TABLE`)
- **`isin VARCHAR(12)`** — Adds the company's ISIN (a standard 12-character global ID) to reliably match the same company across different data sources.
- **`market_cap NUMERIC(20, 2)`** — Stores the company's total market value using exact decimal precision (`BigDecimal` in Java).

#### 2. Creating the `financial_metrics` Table (`CREATE TABLE`)
This table holds the financial statement numbers needed for The Magic Formula:
- **`id BIGSERIAL PRIMARY KEY`** — Auto-incrementing unique ID.
- **`company_id BIGINT NOT NULL`** — Connects this row to the `companies` table.
- **`report_date DATE NOT NULL`** — The date of the financial report (`LocalDate`).
- **Magic Formula Financial Inputs (`NUMERIC(20, 2)`):**
  - **`ebit`** — Operating profit.
  - **`enterprise_value`** — Total value of the business (market cap + debt − cash). Used with EBIT for Earnings Yield.
  - **`current_assets`**, **`current_liabilities`**, & **`net_fixed_assets`** — Used to calculate Return on Capital.
- **`created_at` & `updated_at`** — Automatic timestamps.

#### Constraints
- **`fk_financial_metrics_company_id` (`FOREIGN KEY ... ON DELETE CASCADE`)** — Enforces a strict parent-child link to `companies`.
- **`uq_financial_metrics_company_report_date` (`UNIQUE (company_id, report_date)`)** — Guarantees a company cannot have two separate rows for the same date. Powers idempotent upserts.

<summary><h2 style="display: inline;">6. External API Client & Mappers</h2></summary>

### 6.1 `RoicListResponse.java`
`RoicListResponse.java` lives in `io.github.simeonfarkas.infrastructure.client.dto` and is a generic **Java `record`** used to handle ROIC.AI's API format, which wraps lists inside a data object (`{ "data": [ {...} ] }`).

### 6.2 The Data Transfer Objects (DTOs)
These records map ROIC.AI's JSON keys exactly. `@JsonIgnoreProperties(ignoreUnknown = true)` ensures the parser doesn't crash if the API adds new fields.
- **`CompanyProfileDto`** — Maps `primary_symbol`, `name`, `isin`, `sector`, `industry`, `fundamental_currency`.
- **`IncomeStatementDto`** — Maps `period_end_date` (via Jackson's `JavaTimeModule`) and `ebit`.
- **`BalanceSheetDto`** — Maps `bs_cur_asset_report`, `bs_cur_liab`, `bs_net_fix_asset`, `bs_c_and_ce_and_sti_detailed` (cash), and debt fields.
- **`ValuationMultipleDto`** — Maps `enterprise_value`, `pr_last` (price), and `bs_sh_out` (shares).

### 6.3 `CompanyMapper.java`
Translates external DTOs into your `Company` domain model.
- **Ticker Normalization** — Strips the `STO:` prefix from ROIC.AI symbols (e.g., `"STO:VOLV_B"` $\rightarrow$ `"VOLV_B"`).
- **`calculateMarketCap`** — Multiplies `lastPrice` by `sharesOutstanding`.

### 6.4 `FinancialMetricsMapper.java`
Translates the three financial DTOs into a single `FinancialMetrics` domain record.
- **Enterprise Value Fallback** — Uses ROIC.AI's pre-calculated `enterpriseValue` if available. If missing, computes it manually ($\text{Market Cap} + \text{Total Debt} - \text{Cash}$), substituting zero for missing debt or cash fields safely.

### 6.5 `StockDataApiClient.java`
`StockDataApiClient.java` lives in `io.github.simeonfarkas.infrastructure.client`. Think of it as your application's dedicated messenger to ROIC.AI: it formats stock tickers, obeys API speed limits, sends HTTP requests over the internet, checks for errors, and translates raw JSON text into clean Java domain objects (`Company` and `FinancialMetrics`).

---

#### 1. Class Fields (The Client's Tools & Memory)
At the top of the class, we declare the tools and settings the client needs to keep in memory while running:
- **`private static final Logger log = LoggerFactory.getLogger(StockDataApiClient.class);`** — Creates a logger for this class so warnings and errors are printed with timestamps and severity levels (`WARN`, `ERROR`) instead of plain `System.out.println`.
- **`private static final long RATE_LIMIT_DELAY_MS = 12_500L;`** — A constant (`static final`) defining the minimum pause between API calls in milliseconds (`12,500 ms = 12.5 seconds`). The underscore in `12_500L` is just a Java readability feature (like writing `12,500`), and `L` marks it as a `long` number.
- **`private final HttpClient httpClient;`** — Java 21's built-in HTTP engine. It acts like a headless web browser inside your code that can send requests to URLs and receive responses.
- **`private final ObjectMapper objectMapper;`** — Jackson's JSON translator. It reads raw JSON strings returned by ROIC.AI and populates your DTO `record` classes automatically.
- **`private final String baseUrl;` & `private final String apiKey;`** — Stores the API root address (`https://api.roic.ai/v3.0.0`) and your secret API key, passed in from `Main.java` so no secrets are hardcoded in this file.
- **`private long lastRequestTime = 0L;`** — Acts as a stopwatch. It remembers the exact timestamp (in milliseconds) of the previous API request so the client knows how long it needs to wait before making the next one.

---

#### 2. Constructor (`public StockDataApiClient(String baseUrl, String apiKey)`)
Runs once when you create `new StockDataApiClient(...)` in `Main.java`:
- **`this.baseUrl = baseUrl;`** & **`this.apiKey = apiKey;`** — Saves the URL and key into the class fields above.
- **`this.httpClient = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(10)).build();`** — Builds the HTTP client and tells it to give up if ROIC.AI takes more than 10 seconds just to establish a connection (preventing your program from freezing indefinitely on a dead network).
- **`this.objectMapper = new ObjectMapper().registerModule(new JavaTimeModule());`** — Creates the JSON parser and plugs in `JavaTimeModule`. Without this module, Jackson does not know how to convert JSON date text like `"2025-12-31"` into a Java `LocalDate` object and will crash.

---

#### 3. Fetching the Company Profile (`fetchCompanyProfile(String ticker)`)
This public method takes a ticker (like `"VOLV_B"` or `"NASDAQ:AAPL"`) and returns `Optional<Company>` (a container that either holds a `Company` or is empty if something went wrong):
1. **`String symbol = toRoicSymbol(ticker);`** — Cleans the ticker and adds `STO:` if no exchange prefix is present (e.g., `"volv_b"` $\rightarrow$ `"STO:VOLV_B"`).
2. **`String url = baseUrl + "/company/profile/" + symbol;`** — Glues together the full endpoint address: `https://api.roic.ai/v3.0.0/company/profile/STO:VOLV_B`.
3. **`Optional<RoicListResponse<CompanyProfileDto>> response = getJson(url, new TypeReference<>() {});`**
  - Sends the HTTP request via `getJson(...)`.
  - **Why `new TypeReference<>() {}` is needed:** Because of a Java quirk called *type erasure*, Java forgets at runtime what type is inside `<...>`. Passing an anonymous `TypeReference` subclass preserves the nested generic structure (`RoicListResponse` containing `CompanyProfileDto`) so Jackson knows which record fields to populate.
4. **Unwrapping & Mapping:**
  - Checks if `response` is empty or if `response.get().data()` has no items. If nothing came back, it returns `Optional.empty()`.
  - Otherwise, grabs the first item (`data().get(0)`) and calls `CompanyMapper.toDomain(profile, null, symbol)`.
  - **Why `null` is passed as the second argument:** ROIC.AI's `/company/profile` endpoint only returns static company metadata (name, ISIN, sector, industry, currency)—it does *not* include share price or share count. Because those numbers aren't fetched until `fetchLatestFinancials`, `Company.marketCap` is set to `null` at this stage.
5. **`catch (Exception e)`** — Wraps the entire method in a `try/catch` block. If the network drops or JSON parsing fails for one company, it logs the error and returns `Optional.empty()` instead of crashing the entire screener run.

---

#### 4. Fetching Financial Statements (`fetchLatestFinancials(Company company)`)
Takes an already-fetched `Company` and makes **three sequential API calls** to gather all numbers required by The Magic Formula (~37.5 seconds total because of the 12.5-second pause before each call):
1. **Call 1 — Income Statement:** Queries `/fundamental/income-statement/{symbol}?cadence=annual&limit=1` to get `ebit` (operating profit) and `period_end_date`.
2. **Call 2 — Balance Sheet:** Queries `/fundamental/balance-sheet/{symbol}?cadence=annual&limit=1` to get `currentAssets`, `currentLiabilities`, `netFixedAssets`, cash, and debt.
3. **Call 3 — Valuation Multiples:** Queries `/fundamental/multiples/{symbol}?cadence=annual&limit=1` to get `enterpriseValue`, `lastPrice`, and `sharesOutstanding`.
- **Early Exit Checks:** After each call, if the response or its `.data()` list is empty, the method immediately stops and returns `Optional.empty()` rather than wasting time on incomplete data.
- **Combining the Reports:** Once all three DTOs (`income`, `balance`, `multiples`) are retrieved, it passes their first elements into `FinancialMetricsMapper.toDomain(...)`, which calculates `enterpriseValue` (using ROIC's value or computing it manually as a fallback) and returns `Optional<FinancialMetrics>`.

<summary><h2 style="display: inline;">7. Application Services (Ingestion & Validation)</h2></summary>

### 7.1 `DataIngestionService.java`
`DataIngestionService.java` lives in `io.github.simeonfarkas.application.service`. If `StockDataApiClient` is the messenger and the repositories are the storage clerks, `DataIngestionService` is the **orchestrator** (project manager) that coordinates the entire pipeline from raw stock ticker to validated database records.

---

#### 1. Dependencies & Constructor
The service connects three components through constructor injection:
- **`StockDataApiClient apiClient`** — Fetches company profiles and financial statements from ROIC.AI.
- **`CompanyRepository companyRepository`** — Saves and retrieves `Company` records in PostgreSQL.
- **`FinancialMetricsRepository metricsRepository`** — Saves `FinancialMetrics` snapshots linked to each company.
- **`IngestionSummary` (`record`)** — A lightweight return object (`total`, `succeeded`, `skipped`, `failed`) that gives `Main.java` a clear report of how the batch run went.

---

#### 2. Batch Loop & Fault Isolation (`ingestTickers(List<String> tickers)`)
Instead of wrapping the entire list of 300+ Nasdaq Stockholm companies in one giant database transaction, `ingestTickers` processes **one ticker at a time** inside a `try/catch` block:
1. **Blank Check:** Ignores `null` or empty ticker strings immediately (`skipped++`).
2. **Isolated Execution (`processSingleTicker`):** Calls the 4-step pipeline for a single company.
3. **Failure Containment:** If an unexpected exception occurs for one company (such as a malformed response or database constraint issue), the `catch` block logs the error, increments `failed`, and **continues with the remaining tickers** instead of aborting the entire batch. Because each company takes ~50 seconds due to ROIC.AI's rate limit, saving per company also ensures progress is never lost mid-run.

---

#### 3. The 4-Step Pipeline (`processSingleTicker(String ticker)`)
For each ticker, the service executes four steps in strict order:
1. **Fetch & Validate Profile:** Calls `apiClient.fetchCompanyProfile(ticker)` and runs `isValidCompany(...)`. If the company is missing or inactive, it logs a warning and skips it early—saving 3 unnecessary financial API calls (~37.5 seconds).
2. **Persist Company & Resolve Database ID:**
  - Calls `companyRepository.upsertBatch(List.of(fetchedCompany))` to insert or update the company in PostgreSQL.
  - Immediately calls `companyRepository.findByTicker(...)` to fetch the saved record back. **Why?** A newly created `Company` from the API has `id = null`, and PostgreSQL generates the primary key (`BIGSERIAL`) upon insert. `FinancialMetrics` requires that exact `companyId` foreign key before it can be saved.
3. **Fetch & Validate Financials:** Passes `persistedCompany` (now complete with its database `id`) into `apiClient.fetchLatestFinancials(...)`, then checks the result with `isValidMetrics(...)`.
4. **Persist Metrics:** Saves the validated snapshot via `metricsRepository.upsertBatch(List.of(metrics))` in its own isolated JDBC transaction.

---

#### 4. Data Quality & Validation Rules
Before anything touches the database, two gatekeeper methods ensure incomplete or delisted companies never pollute your Magic Formula rankings:
- **`isValidCompany(Company company)`** — Rejects companies where `isActive` is `false`, or where `ticker`, `name`, or `currency` is missing/blank.
- **`isValidMetrics(FinancialMetrics metrics)`** — Rejects financial snapshots missing `reportDate` or any of the five core Magic Formula inputs:
  - **`ebit` & `enterpriseValue`** — Required to compute **Earnings Yield** ($\text{EBIT} / \text{Enterprise Value}$).
  - **`currentAssets`, `currentLiabilities`, & `netFixedAssets`** — Required to compute **Return on Capital** ($\text{EBIT} / (\text{Net Working Capital} + \text{Net Fixed Assets})$).
